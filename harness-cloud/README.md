# Harness Cloud

Desktop-приложение: режет длинное видео (подкаст, стрим, разговор) на вертикальные клипы.
Для каждого клипа: ранг, оценка «силы момента», обоснование выбора, хук, описание и хештеги.

**Используйте только видео, на которые у вас есть права.**

## Что умеет

- Вход: ссылка (YouTube, Twitch VOD, прямой mp4/m3u8 через yt-dlp) или перетаскивание файла.
  Пакетная очередь: несколько ссылок через пробел или с новой строки.
- Типы контента: «Подкаст / разговор», «Стрим / Игра», «Общее». В режиме «Игра» субтитры и хук не добавляются.
- Выход: 5–10 клипов по 30 с (±0.5 с), H.264 High + AAC, 30 fps, MP4. Формат кадра выбирается в расширенных
  настройках: 9:16 (1080×1920, по умолчанию), 16:9 (1920×1080), 4:3 (1440×1080), 1:1 (1080×1080).
- Кадрирование: «По лицу» — окно нужного соотношения следует за лицом (детекция OpenCV, сглаживание траектории,
  ограничение скорости, fallback на центр). «Вписать с фоном» — весь кадр без обрезки, поверх размытой копии.
- Субтитры (ASS, пословная подсветка), крупный шрифт. Переключатель «Показывать субтитры и хук» выключает оба.
  Субтитры и хук всегда стоят внизу кадра; хук поднят над строкой субтитров. Опции: плашка под текстом,
  эмодзи к ключевым словам, анимация появления слов. Три стиля: фиолетовый, жёлтый, белый минимал.
- Хук: заголовок в первые 2.8 с, вшит в видео. Правила по умолчанию; LLM-вариант при задании `ANTHROPIC_API_KEY`.
- Описания под платформы: вкладки TikTok / Shorts / Reels. У каждой свой текст по лимитам платформы и свои хештеги
  (у Shorts — отдельный заголовок).
- Ручная правка клипов: клик по таймлайну ставит точку и создаёт новый клип на 30 с с этой точки; вырезка
  фрагмента внутри клипа (недостающие секунды добираются из исходника, длина остаётся 30 с); склейка двух клипов
  (по 15 с из каждого). Клипы из нескольких фрагментов не сдвигаются кнопками ±3 с.
- Оценка момента с подсветкой окон клипов на таймлайне исходного видео.
- Предпросмотр в плеере, ручная подрезка начала (±3 с), переключение стиля субтитров и пресета экспорта
  (TikTok / Shorts / Reels) с перерендером без повторной транскрибации.
- Описание и хештеги для каждого клипа, копирование; «Скачать всё» — ZIP с клипами и `metadata.json`.
- История проектов, удаление, повторное открытие, повтор с ошибочного шага, отмена, уведомления о готовности.
- Светлая и тёмная темы (запоминаются), горячие клавиши: пробел — пауза предпросмотра, Ctrl+S — сохранить настройки,
  стрелки — соседний клип.

## Установка и запуск из исходников

Нужны Python 3.11+ и ffmpeg (с libx264, AAC и libass).

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py                        # окно приложения
```

ffmpeg ищется в таком порядке: папка `bin/` рядом с приложением, переменная `FFMPEG_DIR`, затем `PATH`.

Флаги:

- `python run.py --browser` — открыть в браузере вместо окна;
- `python run.py --server --port 8765` — только сервер.

Переменные окружения:

- `HARNESS_DATA_DIR` — папка данных (проекты, модели Whisper, настройки). По умолчанию: `%APPDATA%\HarnessCloud`
  на Windows, `~/Library/Application Support/HarnessCloud` на macOS, `~/.local/share/HarnessCloud` на Linux.
- `FFMPEG_DIR` — папка с ffmpeg и ffprobe.
- `ANTHROPIC_API_KEY` — если задан, хуки генерируются через LLM (модель `claude-haiku-5-5`), при ошибке — правила.

При первом использовании `faster-whisper` скачивает модель выбранного размера (tiny / base / small / medium)
в папку данных. Для этого нужен интернет.

## Тесты

```bash
pip install pytest scikit-image        # scikit-image — только для тестового фото лица
python -m pytest -v tests/test_pipeline.py
```

Тесты генерируют тестовое видео (1920×1080, 240 с): синтетическая русская речь через espeak-ng с точными
таймкодами каждого слова и движущееся фото лица. Фото астронавта из scikit-image — public domain (NASA).
Полный прогон занимает около 9–10 минут на двух ядрах. Что проверяется:

- формат каждого клипа (1080×1920, 30 fps, H.264, AAC, длительность 30 ± 0.5 с);
- непересекающиеся окна, ранги по убыванию;
- лицо в выходном кадре около центра (допуск 12% ширины);
- субтитры: синий подсвеченный текст во время речи, его нет в паузах;
- хук виден в первые 2 с и исчезает к 6 с;
- режим «Игра»: нет субтитров, хука и `sub.ass`;
- fallback без Whisper: клипы создаются, в отчёте есть предупреждение;
- ZIP открывается и содержит клипы и `metadata.json`;
- основные API-эндпоинты.

UI-проверка кнопок в Chrome (Playwright, канал `chrome`):

```bash
HARNESS_DATA_DIR=/path/to/data python run.py --server --port 8799 &
python tests/ui_smoke.py               # берёт первый готовый проект с сервера
```

## Сборка

PyInstaller собирает приложение только для той ОС, на которой запущен, поэтому собирайте на каждой платформе.

- **Windows:** положите `ffmpeg.exe` и `ffprobe.exe` в папку `bin\`, затем `scripts\build_windows.bat`.
  Результат: `dist\HarnessCloud\HarnessCloud.exe`.
- **macOS:** положите статические `ffmpeg` и `ffprobe` в `bin/`, затем `scripts/build_macos.sh`.
  Результат: `dist/HarnessCloud.app`. Для распространения нужны подпись и нотаризация (Developer ID).
- **Linux:** `pyinstaller --noconfirm harness-cloud.spec` (ffmpeg берётся из `PATH`).

Сборка включает `ui/` и `models/`. Размер бинарника около 800 МБ из-за CTranslate2, OpenCV и Qt-зависимостей pywebview.

## Решения

- **Детекция лиц — Haar, не DNN.** Haar-каскад уже есть в колесе OpenCV и работает офлайн. DNN-модели (YuNet, SSD)
  приходится скачивать отдельно. Минус Haar — хуже с поворотом головы и при боковых ракурсах. Нужно это
  учитывать для кадров, где говорящий отвернулся.
- **Субтитры и хук — ASS, вшиваются фильтром `ass` ffmpeg.** Так один проход рендера даёт и подсветку по словам,
  и хук с фоном-плашкой, а `drawtext` не нужен.
- **Кроп — кусочно-линейное выражение `crop` по времени.** Траектория лица сглаживается и ограничивается по скорости,
  затем превращается в выражение для ffmpeg с ключевыми кадрами раз в секунду. Так кадр не дёргается.
- **Ручная подрезка — сдвиг начала на ±3 с, а не две ручки на 30-секундном окне.** Длина клипа остаётся 30 с по спецификации.
- **Оценка «силы момента» — взвешенная сумма:** громкость 25%, плотность речи 25%, смена эмоций 20%, ключевые слова 20%,
  отсутствие длинных пауз 10%. Для «Игры» словарь ключевых слов игровой. Выбранные окна привязываются к ближайшей
  паузе (до 1.5 с), чтобы не резать фразу посередине.
- **Дубликаты:** окна с совпадением текста больше 60% (индекс Жаккара) пропускаются.
- **Очередь — один рабочий поток.** Параллельный рендер на слабой машине даст больше простоя, чем выигрыша.
- **Ошибка одного клипа не останавливает проект.** Остальные клипы рендерятся, ошибка показывается на карточке.
- **Повтор продолжает с упавшего шага.** Готовые загрузка, аудио и транскрипт не пересчитываются.
- **Хук правилами:** берётся самая «цепляющая» фраза (вопрос, восклицание, длина), обрезается до 7 слов.
- **Субтитры всегда внизу.** Раньше стили «верх» и «центр» давали текст над лицом; по требованию всё вынесено вниз,
  отступ пересчитывается под высоту кадра. Выключатель отвечает и за субтитры, и за хук: хук без субтитров не выводится.
- **Склейка и вырезка работают с отрезками исходника.** Клип хранится как список `segments`; при нескольких отрезках
  каждый рендерится отдельно, затем склеивается concat. Вырезка сохраняет 30 с, добирая секунды из исходника.
- **Игровой режим по умолчанию без субтитров**, но переключатель можно включить и для него.

## Ограничения

- Транскрибация требует модель Whisper. Без неё клипы режутся по громкости, речи и паузам, субтитры и хук не добавляются,
  в отчёте проекта появляется предупреждение.
- Длинные видео (3 часа и больше) загружают аудио в память целиком: примерно 700 МБ на 3 часа при 16 кГц float32.
- Скачивание «Скачать всё» в окне pywebview зависит от обработки загрузок конкретной платформой (WebView2, WKWebView).
  Если окно не сохраняет файл, используйте `--browser`.
- Кроп по Haar хуже работает для лиц в профиль и при сильном наклоне головы. Тогда окно центрируется по последнему
  найденному лицу либо по центру кадра.
- Формат 16:9 и 1:1 с кропом «По лицу» показывает почти весь исходный кадр, поэтому эффект следования за лицом
  заметен только в 9:16 и 4:3.
- Вырезка внутри клипа не меняет субтитры по временам: слова берутся из исходника по отрезкам, так что текст
  после склейки отображается по фактическим словам.
- Описания и хештеги формируются правилами (частотность слов клипа). Для качественных описаний включите LLM-хук
  через `ANTHROPIC_API_KEY` или добавьте генерацию описаний в LLM-вариант.

## Установка на Windows

- **Установщик `HarnessCloud-Setup.exe`** (артефакт сборки в CI): ставит в профиль пользователя без прав администратора,
  создаёт ярлык в меню «Пуск» и, по желанию, на рабочем столе. Удаление — через «Программы» или ярлык «Удалить».
- Окно приложения строится на WebView2 (на Windows 10/11 он обычно уже установлен). Если окно не открылось, собранное
  приложение не переходит в браузер, а показывает сообщение с ошибкой и подсказкой поставить WebView2 Runtime.
  Открыть в браузере можно только из исходников: `python run.py --browser`.

## Версия 1.1: что изменилось

- Водяной знак (название канала, до 40 символов) в верхнем правом углу каждого клипа. Задаётся в расширенных настройках
  и меняется для готовых проектов с перерендером.
- Интерфейс переработан по макету: синяя палитра, переключатель светлой и тёмной темы в шапке, карточка обработки с шагами.
- Рендер клипов параллельный: число одновременно рендерящихся клипов — по числу ядер, не больше трёх. Переменная
  `HARNESS_RENDER_WORKERS` задаёт число явно (например, `1` для отладки). Промежуточные отрезки кодируются быстрым
  пресетом, итоговый файл — `veryfast` с тем же CRF.
- Ошибка одного клипа не останавливает остальные: клип получает статус «Ошибка» и попадает в предупреждения проекта.

## Версия 1.2: шрифты, эффекты и положение субтитров

- **Положение субтитров.** На превью есть маркер «Субтитры»: его можно перетащить мышью в любую точку по ширине и высоте
  кадра. Положение сохраняется для клипа в процентах (`sub_x`, `sub_y`), поэтому не зависит от формата кадра. Кнопка
  «Сбросить» возвращает стандартное место (по центру у нижнего края). Перетаскивание запускает перерендер клипа.
- **Шрифты.** Встроенные шрифты лежат в `fonts/`: Inter, DejaVu Sans, Roboto и Open Sans (переменные начертания
  там, где они есть). Список берётся из `GET /api/fonts`. Свой шрифт загружается кнопкой рядом с выбором шрифта или
  через `POST /api/fonts`: принимаются файлы `.ttf` и `.otf` не больше 15 МБ, имя семейства читается из файла.
  Загруженные шрифты лежат в папке данных приложения (`fonts/`) и не попадают в сборку.
- При рендере файлы шрифта семейства копируются в папку клипа, и libass берёт их через `fontsdir`. Поэтому субтитры
  выглядят одинаково на любой машине, даже если шрифт не установлен в системе.
- **Эффекты субтитров.** Выбираются в настройках: «Без эффекта», «Плавное появление» (`\fad`), «Выезд снизу»
  (`\move`), «Свечение» (размытый контур) и «Всплеск слов» (анимация слов, включает анимацию субтитров).
- **Лицензии.** Шрифты распространяются по лицензиям SIL OFL и Bitstream Vera; тексты и источники — в
  `fonts/LICENSES.txt`. Добавлять в `fonts/` можно только шрифты, которые разрешено распространять.

## Версия 1.3: папка сохранения и поиск динамичных моментов

- **Папка сохранения.** В настройках задаётся «Папка сохранения» (полный путь, папка создаётся сама). Кнопка
  «Выбрать…» открывает системный диалог в окне приложения; в браузерном режиме путь вводится вручную.
  Если папка задана, после каждой обработки и перерендера готовые клипы и ZIP копируются в
  `<папка>\<название проекта> [<id>]\`. Пункт меню «⋯ → Сохранить в папку» копирует их вручную.
  Без папки всё остаётся в папке данных приложения, а «Скачать» работает через браузер.
- **Поиск моментов по динамике.** Раньше окна ранжировались по средней громкости и плотности речи, поэтому
  выигрывал ровный громкий кусок. Теперь громкость каждой секунды сравнивается с фоном (медиана за 31 с),
  и сильный момент — это резкий всплеск над фоном, нарастание к кульминации, перепады громкости внутри окна,
  удары (скачки больше 6 дБ за 0.1 с) и смена темпа речи. Ключевые слова добавляют баллы, длинные паузы
  и окна без пиков — штраф. Тесты: `tests/test_scoring.py`, `tests/test_savedir.py`.
- Исправлено: после смены стиля или формата кадра редактор на короткое время показывал «Готово» вместо
  «В очереди» (статус ставится только при старте рабочего потока).

## Версия 1.4: качество и частота кадров

- **Качество** выбирается для каждого проекта в расширенных настройках: 480p, 720p, 1080p, 2K (1440p), 4K (2160p).
  Значение задаёт короткую сторону кадра, соотношение сторон берётся из формата кадра. Например, 9:16 в 720p — 720×1280.
- **Частота кадров** — от 20 до 120 FPS (20, 24, 25, 30, 48, 50, 60, 90, 120). Допустимо любое целое в этом диапазоне через API.
- Клипы рендерятся в выбранных качестве и частоте, скачиваются в них же, и так же сохраняются в папку сохранения и в ZIP.
  Изменение в расширенных настройках перерендерит клипы. В `metadata.json` внутри ZIP есть формат, качество и FPS каждого клипа.
- Битрейт пресета (TikTok, Shorts, Reels) масштабируется по числу пикселей в секунду относительно 1080×1920 при 30 fps.
  4K при 60 fps получает пропорционально больший битрейт, 480p — меньший.
- Вкладка «О приложении» переписана: основные возможности, качество и экспорт, источники, для кого.
- Тесты: `tests/test_quality.py` (размеры, частота, битрейт, API, реальный рендер 480p/20 fps и 720p/60 fps).

## Версия 1.5: значения по умолчанию, оценка времени, план публикации, порог автосохранения

- **Качество и частота кадров по умолчанию** задаются в настройках и подставляются в новые проекты.
- **Оценка времени рендера.** Под кнопкой «Начать обработку» показывается примерное время рендера клипов с учётом
  качества, частоты кадров, формата и числа клипов. Оценка уточняется по фактическим рендерам: скорость хранится в
  `calibration.json` в папке данных. Пока замеров нет, используется значение по умолчанию, и строка это пишет.
- **Порог автосохранения.** В настройках можно задать минимальную силу момента (0–100). Автоматически в папку сохранения
  попадут только клипы не ниже порога. Клипы без оценки (добавленные вручную) сохраняются всегда. Кнопка
  «Сохранить в папку» сохраняет все клипы.
- **Расписание публикаций.** В редакторе клипа можно указать дату и время публикации. Дата попадает в `metadata.json`
  внутри ZIP. Приложение **не публикует видео само**: это план для ручной публикации.

## Версия 1.9: тип «Видео по частям», длительность клипа для всех типов

- **Тип «Видео по частям».** Видео режется подряд с самого начала на части выбранной длины. Выбор лучших моментов отключён: первая часть всегда начинается с нуля, каждая следующая продолжает предыдущую без пропусков. Субтитры включены, хук — по переключателю.
- **Длина.** Выбор «Длительность клипа» теперь работает для всех типов: 30 с, 45 с, 1 мин, 1 мин 30 с, 2 мин, 2 мин 30 с, 3 мин. Для обычных типов клипы выбираются по скорингу именно такой длины. Для «по частям» это длина каждой части.

- Проверка готового файла учитывает фактическую длину клипа, поэтому части длиннее 30 с больше не отбраковываются.
- Тесты: `tests/test_parts.py`, включая сквозной прогон на синтетическом видео (части идут подряд с нуля, длины совпадают).
- В режиме «по частям» этап называется «Нарезка моментов» (вместо «Поиска сильных моментов»). У карточек вместо полосы «Сила момента» показывается длительность части, бейдж на превью показывает реальную длину (например, 1:00), а шкала в редакторе подписана как громкость по времени.
- Ограничение: на реальном видео с речью и на длинных видео (часы) не проверено. Скорость рендера частей по 3 мин не замерялась.

## Версия 2.0: субтитры без наложения, звук, новые анимации

- **Наложение субтитров исправлено.** Причина: строки могли выводиться одновременно, потому что конец каждой группы слов не обрезался началом следующей. Теперь конец строки ограничен началом следующей группы с зазором 0.02 с (`NO_OVERLAP_GAP` в `harness/subtitles.py`). Тест `test_subtitle_lines_never_overlap` проверяет это на 40 словах.

Тест `test_rendered_clip_is_normalised_to_target_loudness` измеряет громкость через `ebur128` и допускает отклонение ±1.5 LU.
- **Ограничение:** одноходовой `loudnorm` приближает громкость, но не точно, потому что не знает заранее, сколько её нужно поднять или опустить. Двухходовой режим (сначала измерить, потом применить) даст точнее. Он запланирован отдельно.

## Версия 2.1: Нарезка Live (запись эфира и нарезка на ходу)

- Новая вкладка **«Нарезка Live»** (рядом с «История»). Вставляете ссылку на эфир Twitch, YouTube или Kick, выбираете тип контента и подтверждаете права на трансляцию. Без подтверждения запись не запускается (сервер вернёт 400).
- **Как работает.** `yt-dlp` находит поток эфира, ffmpeg пишет его сегментами по 60 с (`harness/live.py`, `SEGMENT_SEC`). Каждые 5 минут (`WINDOW_SEC`) сегменты склеиваются без перекодирования в одно окно. Окно становится обычным проектом и уходит в очередь: транскрипция, поиск моментов, субтитры и рендер — те же, что для загруженного видео.
- **Хвост записи.** При остановке последний неполный кусок обрабатывается, если он не короче 2 минут (`MIN_TAIL_SEC`). Более короткий отбрасывается.
- **Остановка.** Кнопка «Остановить запись» завершает ffmpeg и отдаёт остаток в обработку. Если эфир закончился сам, статус «Эфир закончился».
- **Ограничения, которые важно знать:**
  - сессии записи живут в памяти приложения: при перезапуске незавершённая запись останавливается, уже созданные окна остаются в «История»;
  - нужно, чтобы приложение было открыто, а эфир шёл;
  - `yt-dlp` зависит от того, как сайт отдаёт поток, и может перестать работать после изменений на стороне платформы: тогда обновляйте зависимость;
  - в этой среде сборки нет доступа к живым эфирам, поэтому запись проверена подменой (тесты в `tests/test_live.py`: нарезка окна, хвост, отказ без прав), а не на реальной трансляции. Проверка на настоящем эфире за вами.
- **Права.** Приложение записывает только то, на что у вас есть права. Подтверждение в интерфейсе — это ваша отметка, а не проверка платформы.
- Версия приложения: 2.1.0.
